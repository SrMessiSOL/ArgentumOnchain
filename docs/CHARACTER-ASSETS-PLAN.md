# Character assets and item exports — implementation decision

Characters use Metaplex Core NFTs on Solana devnet. Existing characters are migrated only when their owner chooses Mint; new characters require minting/staking before world play. Mint issues the NFT directly to the linked wallet, initially frozen/staked. No realtime game actions go on-chain.

The existing database remains the gameplay source of truth. NFT ownership authorizes the character; a frozen asset with the game's delegated freeze authority authorizes play. The operator co-signs mint, stake, settlement and marketplace delivery. This first version deliberately trusts the game operator, like the existing gold mint authority; it is not a trustless Anchor staking program. No permanent delegates are used. A normal Transfer Delegate allows the website to atomically transfer an unstaked/listed asset with SOL payment; it resets on ownership transfer. Stake reauthorizes it with explicit wallet signature.

Unstake requires an offline character, invalidates tickets, reserves the character, persists an immutable canonical full-bundle snapshot and commits its version/hash through Attributes in the same chain transaction that thaws it. The DB transaction and chain transaction are separate; persisted exact signed bytes, receipt finality and idempotent recovery bridge them. No unlock on ambiguous RPC errors. New owner stakes the registered NFT to claim the same character ID and its inventory/bank/spells/progression/titles; stale sessions are invalidated.

Items remain database inventory. Export reserves/removes the selected eligible, unequipped quantity while the character is offline; mint creates a receipt NFT for that item/quantity. Confirmed expiry restores it once; finalized mint leaves it out of the character bundle. Import checks current asset ownership, burns that exact registered receipt, and adds the stored item/quantity exactly once to an offline playable character. Never trust wallet-provided item IDs or quantities. Existing legacy item listings remain compatible; NFT item trading uses wallet transfers initially.

Limits: no mainnet, no automatic real wallet signing, no destruction of legacy data, no account vault included in character bundle, no new standalone smart-contract deployment. Public metadata exposes summary only; full snapshots remain server-side. Existing badges remain attached to character ID. Bank and inventory transfer with the character, including ordinary off-chain gold. Operations must prohibit mixed pending exports, marketplace escrow, login leases, and snapshots.

Validation: isolated PostgreSQL + mocked-chain lifecycle tests; real instruction/message signature and SDK decoding tests; production API/frontend builds; unsigned devnet simulation if available. Live mint/stake/unstake/burn/payment require the human wallet and will be reported separately from simulated tests.
